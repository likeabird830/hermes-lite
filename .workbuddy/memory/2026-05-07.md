## 🧠 Hermes v2.3 升级 — 动态技能扫描引擎 ✅（09:09）

### 用户反馈
用户指出 Hermes 太"笨"：问多少个 skills 它只是读知识库/记忆里的硬编码数字（104），而不是真正去扫描计数。要求让它变"聪明"。

### 根因分析
| 问题 | 位置 | 影响 |
|---|---|---|
| **纯死记硬背** | `build_messages()` 把 `_knowledge[-12:]` 当文本注入 LLM | LLM 只能重复它看到的数字 |
| **知识库被自动保存破坏** | `gh_upload_memory()` 每次把 KB 重写成简化 `- entry` 格式 | 丢失分类、编号等结构化数据 |
| **无动态扫描能力** | 没有 function calling / tool use / 文件系统访问 | 无法自己数 |

### v2.3 改动清单 (commit `33f05f1`)

#### 新增：`parse_skill_entries()` — 智能知识库解析器
- 正则匹配 `"123. **Name** — desc | 触发：xxx"` 格式
- 自动识别 `## 分类标题` 作为 category 分组
- 跳过 Git 冲突标记 (`<<<<<<<`, `=======`, `>>>>>>>`)
- 返回：总数 + 分类列表 + 条目详情

#### 新增：`scan_skills_dynamic()` — GitHub API 动态扫描
- 通过 GitHub Contents API 实时拉取 `hermes_knowledge.md`
- 调用 `parse_skill_entries()` 解析统计
- **5分钟缓存**避免频繁调用 API
- 返回：total, categories, entries_count, SHA

#### 新增：`get_skill_count_for_prompt()` — 注入 LLM 的摘要格式
- 生成人类可读的技能统计快照
- 包含分类分布和 SHA 校验值

#### 修改：`build_messages()` → async + 动态注入
- 变成 async 函数（因为要 await 扫描）
- **每次对话都注入实时技能数**到 system message
- 问 skill 相关问题时注入完整统计；其他查询注入紧凑版

#### 新增：`!skills` 命令
- Discord 命令，触发完整技能扫描并展示 Embed
- 显示总数、分类分布、数据源信息、缓存时间

#### 修复：`gh_upload_memory()` 不再破坏知识库
- **v2.3 关键改动**：只上传 profiles，跳过 knowledge base
- 知识库现在由手动维护（保留 Markdown 格式）
- 这解决了"自动保存覆盖精心编排的知识库"问题

#### 修改：System Prompt 新增"动态计数规则"
- 明确告诉 Hermes：不要用旧数字回答，用实时扫描数据
- 不确定就查，不要猜
